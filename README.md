# Vista

A round Galaxy Watch 7 watch face. Solid black dial, static gray
mountain silhouettes, a sun that crosses the upper arc from 6:00 to 18:00, a
moon on the same arc from 18:00 to 6:00, a large 12-hour digital time, a short
date, a battery aurora across the sky, and two user-changeable complications
(12 o'clock defaults to heart rate, 6 o'clock defaults to steps).

## Format

This is a [Watch Face Format](https://developer.android.com/training/wearables/wff)
(WFF) **version 2** project. The layout is `watchface/src/main/res/raw/watchface.xml`.
There is no app code (`android:hasCode="false"`). The Wear OS watch face runtime
renders the XML.

Version 2 is the version Galaxy Watch 7 launched with (Wear OS 5, API 34). It
still installs on a Watch 7 that has been updated to Wear OS 6. WFF version 4
needs Wear OS 6, and the public compatibility table does not list a Wear OS
release for version 5, so version 2 is the newest version that runs on every
Galaxy Watch 7. Every element used here exists in version 1 except
`GOAL_PROGRESS`, which is a version 2 complication type. Samsung's
[August 2025 WFF guide](https://developer.samsung.com/sdp/blog/en/2025/08/14/building-a-watch-face-with-watch-face-format)
uses the same version and the same minimum SDK.

The coordinate space is 450×450 with `clipShape="CIRCLE"`. That is not the
panel resolution. The runtime scales it. Galaxy Watch 7 panels are 432×432
(40 mm) and 480×480 (44 mm).

`watchface.xml` was checked with the official validator from
[google/watchface](https://github.com/google/watchface) (`wff-validator.jar`
1.7.0, schema version 2):

```text
java -jar wff-validator.jar 2 watchface/src/main/res/raw/watchface.xml
INFO: ✅  PASSED : watchface/src/main/res/raw/watchface.xml is valid against watch face format version #2
```

The debug APK builds with the Android SDK at `/opt/android-sdk`
(`ANDROID_HOME=/opt/android-sdk ./gradlew :watchface:assembleDebug`) and
passes Google's `memory-footprint.jar` check (about 3.0 MB active, 3.8 MB
ambient). The Gradle project is the same shape as Google's
[SimpleDigital sample](https://github.com/android/wear-os-samples/tree/main/WatchFaceFormat/SimpleDigital).

## What the face does

- Background `#ff000000`. Mountain silhouettes are a static drawable image,
  `res/drawable/mountains.png`, drawn with `PartImage`
  (`Image resource="mountains"`). WFF has no polygon element, so the ridges
  live in that PNG instead of `Rectangle` scanlines.
- Sun, 06:00 inclusive to 18:00 exclusive. Moon otherwise, including exactly
  18:00. Same arc: left (9 o'clock) at the start, top at the midpoint, right
  (3 o'clock) at the end. Position uses `sin` / `cos` / `rad` on
  `[SECONDS_IN_DAY]`, so it moves through the hour, not in hour jumps.
  `[SECONDS_IN_DAY]` is re-evaluated every second.
- Time: `TimeText` `format="h:mm"` `hourFormat="12"`. No AM/PM and no seconds.
- Date: `[DAY_OF_WEEK_S]` and `[DAY]`, for example `Sun 4` in English.
- Battery: an aurora across the sky (the old rim `Arc` is gone). Three wavy,
  translucent ribbons sit behind the comet, mountains, sun/moon and time. They
  start at the left edge (x = 0) and end at x = `4.5 * [BATTERY_PERCENT]`, so
  the length is the battery percent of the 450 px sky width (50% stops at the
  centre line, 100% reaches the right edge).
  Colour: under 25% red `#FF3B30`, 25–80% inclusive blue `#3D8BFF`, over 80%
  green `#34C759` (a `Condition` with three branches).
  The aurora is still: no time-driven motion. Its only Transforms are the
  battery-fill `startAngle` / `endAngle` ones described below.
  How it is drawn: WFF v2 has no path element, so each ribbon is an arc
  spline, a chain of `Arc`s whose tangents match at every joint, which reads
  as one smooth wave. Each ribbon is one `PartDraw` with a soft glow made of
  four stacked strokes (wide and faint to thin and bright, alpha in the stroke
  colour) plus a "curtain" haze above it (the same arcs lifted up, stroked
  with a `LinearGradient` that fades to clear). Every `Arc` keeps its left end
  fixed and a `Transform` moves its right end to the fill edge:
  `endAngle = deg(asin((clamp(E, xL, xR) - cx) / r))` for crests (dips move
  `startAngle` the same way). Arcs past the edge collapse to a 0.02 px sliver,
  so no arc ever has a zero or negative sweep.
  The XML block is generated by `tools/gen_aurora.py` (edit the ribbon
  table there and rerun it). `tools/preview_aurora.py PERCENT out.png`
  evaluates the same expressions and renders a preview.
- Complications are real `ComplicationSlot`s (`isCustomizable="TRUE"`), not
  fixed text. Slot 1 at 12 o'clock defaults to `HEART_RATE` / `SHORT_TEXT`.
  Slot 2 at 6 o'clock defaults to `STEP_COUNT` / `SHORT_TEXT`. Both slots also
  accept `RANGED_VALUE`, `GOAL_PROGRESS`, `MONOCHROMATIC_IMAGE`, `SMALL_IMAGE`,
  and `EMPTY`.

`preview-1430-30pct.png` (and the identical picker preview at
`watchface/src/main/res/drawable/preview.png`) is rendered by
`tools/preview_aurora.py` at 14:30 with the battery at 30% (blue aurora,
default cyan comet). `preview-aurora-12pct.png` and `preview-aurora-92pct.png`
show the red and green states. The "72" and "8420" on that PNG are only there to
show the default complication slots. They are not in `watchface.xml`.

## Install on a Galaxy Watch 7

1. Install Android Studio with Android SDK 34 (Wear OS 5). The project uses
   Android Gradle Plugin 9.0.0 and Gradle 9.2.1, copied from the current Wear
   OS samples, so use a current Android Studio.
2. Open this directory (`settings.gradle.kts` is the project root).
3. On the watch: Settings → About watch → Software information → tap Software
   version until developer mode turns on. Then Settings → Developer options →
   turn on ADB debugging and Debug over Wi-Fi. Note the IP and port.
   Pairing steps are in Samsung's
   [Wi-Fi debugging guide](https://developer.samsung.com/sdp/blog/en/2023/11/14/connecting-galaxy-watch-to-watch-face-studio-over-wi-fi).
4. From the computer:

   ```bash
   adb pair WATCH_IP:PAIR_PORT
   adb connect WATCH_IP:DEBUG_PORT
   ```

5. In Android Studio, select the watch and press Run on the `watchface`
   module. The [WFF setup guide](https://developer.android.com/training/wearables/wff/setup)
   says Run deploys the face and makes it the active one.

   Or build and sideload it yourself:

   ```bash
   ./gradlew :watchface:assembleDebug
   adb install -r watchface/build/outputs/apk/debug/watchface-debug.apk
   ```

   Then on the watch, press and hold the current watch face, swipe to
   **Vista**, and tap it.
6. Change the complications: long-press Vista, tap the pencil. Tap the
   12 o'clock slot or the 6 o'clock slot and pick a different complication.
   `watch_face_info.xml` sets `Editable` to true so that pencil is shown.

The debug APK is signed with the Android debug key. That is enough for a
watch you own. A Play upload needs your own release key (`isShrinkResources`
must stay false).

## Expressions that the docs do not fully pin down

`TimeText` format `h:mm` is legal (the version 2 XSD pattern allows
`h{1,2}:m{1,2}`, and `hourFormat="12"` is an official value). The reference
example for `h:mm` is "12:34", so it does not actually show that 2:30 renders
as `2:30` rather than `02:30`. `hh:mm` is the zero-padded form, so `h:mm` is
the unpadded one. If a device renders a leading zero, change the format to
`h:mm` still and file it; there is no other no-seconds, no-AM/PM token.

The Arc reference does not say whether a sweep of exactly 0 or 360 degrees
draws nothing or a full circle. The aurora never asks for either: every arc
sweeps less than 90 degrees, and unreached arcs keep a 0.02 px sliver
instead of a zero sweep. That sliver is too thin to see. `asin`, `deg` and
`clamp` are version 1 expression functions.

The moon's crescent is a second black `Ellipse` offset inside the same
`PartDraw` (`x="10" y="-2"` on a 28px part). Negative coordinates are valid
(the Complications sample uses them). If the runtime clips a `PartDraw` to its
own box, that offset disc is partly clipped and the crescent will look shallow.
The light disc underneath still tracks the arc.

`[COMPLICATION.RANGED_VALUE_VALUE]`, `[COMPLICATION.RANGED_VALUE_MIN]`,
`[COMPLICATION.RANGED_VALUE_MAX]`, `[COMPLICATION.GOAL_PROGRESS_VALUE]`, and
`[COMPLICATION.GOAL_PROGRESS_TARGET_VALUE]` are copied from the official
Complications sample. They are not listed in the version 2 `sourceType` enum.
The XSD still accepts them because an arithmetic expression may be a string.
